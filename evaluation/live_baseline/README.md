## 目的与边界

本目录用项目现有的 `backend/src/taobao.mjs` 实时调用淘宝联盟接口，完成一条充电宝需求的配对 A/B 试运行。A 组只反馈满意或不满意；B 组每次不满意后按预定顺序补充一项需求。两组均不由系统主动提问。每批最多展示 3 件，最多 5 批。

这是独立的**检索实验脚本**，不调用当前 Wit 问卷智能体。用户满意度由事先固定的标题短语和价格规则模拟；商品标题是卖家描述，尚未经人工核实，也不代表真实用户的购买满意度。一次配对结果仅能检验流程，不能推断 B 组整体优于 A 组。

## 实验材料

`scenario.json` 固定初始输入、隐藏判定条件和 B 组逐次反馈。当前样本：初始只说“我想买一个充电宝”；隐藏条件为价格不超过 100 元、标题同时包含“10000毫安”和“自带线”。B 组依次补充容量、自带线、预算。第三条只有前两条反馈后仍未成功才会使用。

同一条需求分别跑 A、B。首次检索结果共享，确保两组首批商品完全相同。A 组按原查询结果顺序继续展示；B 组将已透露的条件加进后续查询。两组分别排除已展示过的 ID 与同标题商品。每批不足 3 件或接口异常时，日志照实记录停止原因。

## 运行

在仓库根目录执行：

```powershell
node --env-file=backend/.env evaluation/live_baseline/run.mjs
```

`backend/.env` 需在本机配置淘宝联盟 App Key、Secret、推广位和关键词搜索接口；文件被 Git 忽略。脚本仅输出非密钥信息。每次运行创建 `runs/<UTC 时间>/events.jsonl` 和 `summary.json`。`events.jsonl` 按时间记录实验配置、搜索词与筛选条件、淘宝返回的商品、每批展示与逐项判定、用户反馈和停止原因。推广链接中的跟踪参数未写入公开日志。

核对本次已保存的试运行：

```powershell

```

## 指标口径

- **5 批内成功**：任一批 3 件商品中至少一件通过预设规则；若 5 批均无合格商品，则为失败。
- **成功批次**：第一次出现合格商品的批次；失败时留空，不能计为第 6 批。
- **属性补充次数**：B 组在成功之前实际发送的附加条件数量。
- **首批成功**：第 1 批是否出现合格商品。
- **重复推荐**：同组后续批次重复出现相同 ID 或标题的商品数。

汇总时先报告每组成功数/样本数，再报告成功样本的批次；失败样本也需单独展示。当前仅一条样本，不计算有统计意义的平均值或组间显著性。

## 扩展前的工作

正式扩展应先让人工核查商品详情、实际规格和价格，再确定多条真实需求及其满意判定。若要评估现有 Wit 智能体，需要另做一个禁用问卷的适配层并验证其推荐逻辑；本脚本的结果不能直接当作现有 Wit 智能体的表现。
