# 淘宝实时商品推荐基线试运行报告

**运行时间：**2026 年 11 月 5 日，北京时间约 11:10

**实验记录：**`runs/2026-11-05T03-09-59-470Z/`
**实验样本：**1 条充电宝购买需求，分别运行 A、B 两组。

## 实验设置

两组初始输入均为“我想买一个充电宝”，首批共用同一次淘宝联盟实时检索结果。隐藏的合格条件在检索前写入 `scenario.json`：价格不高于 100 元，商品标题同时包含“10000毫安”和“自带线”。每批展示 3 件商品，最多 5 批。A 组不提供额外条件；B 组每次不满意后依次补充容量、自带线、预算。判定程序逐件检查价格与标题，不根据实验结果更改条件。

本次共发起 3 次淘宝接口请求：首次共享检索 1 次，B 组补充条件后的检索 2 次。A 组后续批次从首次检索结果依次取出。完整接口返回、展示商品、反馈与停止原因保存在 `events.jsonl`；汇总与逐批判定保存在 `summary.json`。

## 结果

| 指标 | A：只反馈满意与否 | B：每次不满意后补充一项需求 |
| --- | ---: | ---: |
| 5 批内成功 | 否（0/1） | 是（1/1） |
| 实际展示批次 | 5 | 3 |
| 首次出现合格商品 | 未出现 | 第 3 批 |
| 实际补充属性 | 0 | 2 |

| 同组重复 ID 或标题 | 0 | 0 |

两组首批均无合格商品。A 组在第 5 批达到上限，15 件展示商品均未同时符合三个条件。B 组第一次补充“10000毫安”、第二次补充“自带线”后，第 3 批出现一件标题包含两项要求、接口价格为 89 元的商品，规则判定成功。预算条件尚未对系统透露，因第 3 批已成功而未触发后续反馈。该件商品的标题为“【3C认证】CUKTECH酷态科CP13电能块自带线33W快充电芯10000毫安时充电宝小巧移动电源适用于iPhone苹果18”。

## 解释与限制

这一次配对试运行证明实验脚本能连接真实淘宝接口、固定首批条件、执行两种反馈流程，并输出可追溯的完整日志。**1 条样本不能证明逐步补充属性普遍更有效。**A 组的“5 批未成功”也不等于它永远无法找到合格商品；本次只观察到预设的 5 批上限。

合格判定依赖接口价格与卖家标题，没有人工打开详情页验证实际容量、线缆、库存或最终成交价。因此报告中的“成功”是**规则判定成功**，尚不是用户真实满意。现有 Wit 智能体会主动问卷，本次实验使用独立的无追问检索脚本，不能将结果视作该智能体的端到端表现。
