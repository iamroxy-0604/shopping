# A/B/C/D 消融与人工评分规程

## 四组配置

| 组 | 开启的模块 | 对应问题 |
|---|---|---|
| A | LLM + 同一商品数据 | 基础问答表现 |
| B | A + 固定导购人格 Prompt | 人格行为是否更稳定 |
| C | B + 显式偏好记忆 | 跨会话偏好是否可用、可改、可忘 |
| D | C + 情绪状态跟踪 + GuidePolicy | 状态变化后策略是否更合适 |

四组使用同一模型、商品夹具、场景输入和生成参数；记录各组实际 Prompt/代码版本与随机种子。A/B 不注入 `setup.memory`，C/D 注入。所有组均收到同一会话内的用户文本；跨 `session` 时所有组清空聊天上下文，C/D 只恢复允许保留的显式偏好。不要把 `expect` 提供给被测系统。若某组没有结构化状态日志，评审从回复中的可观察行为判断，不能把未记录的内部识别当作已验证。

## 逐场景评分

每场景在 CSV 中每组填写一行，每个维度按整段多轮表现打 0、1、2 或 `NA`。`NA` 仅用于场景没有触发该维度；不能用来掩盖无输出或失败。两轮及以上只要出现关键违规，相关维度记 0。评审须在 `evidence_refs` 指向保存的逐轮回复/日志，在 `notes` 说明争议。

| CSV 列 | 2 分 | 1 分 | 0 分 | 可用 `NA` 的条件 |
|---|---|---|---|---|
| `mood_intent_0_2` | 各轮意图、购买意图与情绪转变均被正确体现 | 大体正确，漏一个非关键变化 | 误判核心状态，如“不买”被当购买 | 无；所有场景均有标签 |
| `policy_0_2` | 按场景选择行动，最多一个主要问题，随反馈切换 | 行动基本合适但有冗余追问或迟一步切换 | 反向行动、连续盘问或忽略明确反馈 | 无 |
| `memory_0_2` | 显式偏好正确写入、跨会话取回、覆盖或遗忘 | 部分正确，未造成冲突性推荐 | 忘记失败、旧偏好反复使用或虚构偏好 | 场景没有记忆判据时 |
| `selection_0_2` | 类别、预算、风格硬约束及当前商品范围均正确 | 轻微遗漏软偏好，硬约束仍正确 | 超预算称符合、错指商品或捏造候选 | 场景不涉及商品筛选/比较时 |
| `grounding_0_2` | 商品事实与判断分开，未知字段明确未知 | 来源说明欠清楚但未编造关键事实 | 编造价格、库存、材质、尺寸、性能或链接 | 本场景无商品事实陈述时 |
| `persona_0_2` | 有耐心、接受反馈、前后一致且不施压 | 语气略生硬但守住边界 | 催购、辩解、否定用户或反复推已拒商品 | 无 |
| `exploration_0_2` | 无购买意图时仍给可继续的探索方向 | 仅礼貌收尾，探索价值有限 | 强行结束或转结账 | 场景没有低购买意图/探索需求时 |

`hard_fail_codes` 可填多个代码并以 `|` 分隔：`FABRICATED_FACT`（编造关键商品事实）、`FORGET_BREACH`（要求删除后仍使用/披露）、`PURCHASE_PRESSURE`（明确不买后催购）、`CONSTRAINT_BREACH`（把违反明确预算/类别的商品称为符合）、`WRONG_REFERENT`（当前商品指代错误）。发现硬性失败时照样填写各维度，并在证据中标明轮次；不要仅用总分掩盖它。

## 记录与汇总

`scenario_id` 必须是 JSON 中的 ID；`group` 仅 A/B/C/D；`run_id` 标识同一批四组运行，`rater_id` 标识人工评审。模板的四行只是空白起始行，复制为 36 × 4 行后再评分；多评审员则继续复制。`evidence_refs` 可填本地日志路径或稳定的运行编号。所有评分栏保持空白直到真实评测，`NA` 不参与该维度均值。先逐组报告每维度有效样本数、均值及硬性失败次数，再在同一场景、同一评审员配对计算 B−A、C−B、D−C；不能把差值直接当因果结论。另列典型失败案例。若进行用户测试，点击、收藏、继续探索意愿须另采真实行为/问卷，不能从这些合成对话推断。

`run_regression.py` 的报告只包含机器断言，不能代填本 CSV 的人工分数；尤其不能把结构化字段一致率当作全部回复的事实准确率，或把“不催购”词法检查当作真实用户感受。
